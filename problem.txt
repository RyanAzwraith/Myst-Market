I found a real authentication-state problem in the source.

## Main source bug

The authentication state has two separate pieces:

- `accessToken` determines whether the user is logged in.
- `user` contains the user model and is the only value persisted.

In `state.ts`,
the persisted state is explicitly limited to:

```ts
partialize: (state) => ({
    user: state.user
}),
```

However, on application startup,
`Scaffold.tsx`
always calls `refresh()`. The refresh endpoint returns only an access token, and
the refresh handler only updates the token:

```ts
refresh: (accessToken) => {
    set({ accessToken })
}
```

Therefore, this state is possible:

```ts
{
    accessToken: "valid-token",
    user: null
}
```

The application then considers the user logged in because:

```ts
isLoggedIn: () => get().accessToken !== null
```

But the profile has no user model to display. This matches the behaviour you
described: the UI acts authenticated while the user information is missing.

The source involved is:

- `state.ts`
- `service.ts`
- `Scaffold.tsx`

## Direct `/login` navigation

The direct login-page behaviour is also explained by the current routing:

```tsx
<ProtectedRoute
    allowed={!accessToken}
    redirect={PageRoutes.profile}
    child={<LoginPage />}
/>
```

If you navigate to `/login` inside the already-running SPA after logging in,
the in-memory `accessToken` remains set. The route correctly redirects to
`/profile`; local storage is not the source of that token.

On a full browser reload, the refresh cookie can also restore the token. The
refresh cookie is HttpOnly, so it will not appear in local storage.

## Additional authorization bug

There is another related source issue in
`PageRoutes.tsx`:

```tsx
const isAdmin = useAuthState(state => state.user?.isAdmin)
```

Admin routes are protected using `isAdmin`, but not `accessToken`. If a stale
or persisted admin user exists while the access token is absent, the admin UI
and admin routes can appear available without an authenticated session.

The same inconsistency exists in `AppBar.tsx`,
where admin mode is based only on `user?.isAdmin`.
